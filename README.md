# Bioconductor Package Binary Builder

A scalable Kubernetes-based system for building Bioconductor package binaries automatically. This system resolves dependencies, schedules builds efficiently, and creates a standard R package repository structure.

## How To Use

### Prerequisites

- **Kubernetes cluster** with sufficient resources
- **kubectl** configured with access to your cluster
- **Storage class** that supports ReadWriteMany access mode (e.g., NFS)
- **GitHub repository** forked or cloned from this codebase
- **GitHub Secrets** configured (see below)

### Required Secrets

Set up the following secrets in your GitHub repository:

- `PAT`: GitHub Personal Access Token with repo permissions
- `KUBECONFIG`: kubeconfig file for your Kubernetes cluster
- `RCLONE_CONF`: Configuration for rclone to access your storage destination

### Starting a New Build Cycle

You can start a new build cycle in two ways:

1. **Manually via GitHub Actions**:
   - Go to the "Actions" tab in your repository
   - Select the "Build R Packages" workflow
   - Click "Run workflow"
   - Check the "Reset" option to start a new cycle

2. **Automatic Schedule**:
   - The system automatically starts a new cycle weekly
   - It also continues in-progress cycles every 5 minutes

### Monitoring Build Progress

1. **Main README**: This page shows an overview of all build cycles
2. **Cycle README**: Click on a Run ID to see detailed status for that cycle
3. **GitHub Actions**: The "Build R Packages" workflow shows real-time logs
4. **Kubernetes**: Use `kubectl get jobs -n ns-{RUN_ID}` to see job status

### Using the Built Packages

The binary packages are stored in a cloud storage endpoint specified in your rclone configuration. Users can install them with:

```r
# In R
options(BioC_mirror = "https://your-storage-endpoint.com/bioconductor-packages/[version]")
BiocManager::install("PackageName")
```

### Troubleshooting Failed Builds

1. Check the detailed logs for each package in `runs/{RUN_ID}/logs/{PACKAGE}/build-fail.log`
2. Use the `reset_failed.sh` script to reset failed packages for retry:
   ```bash
   ./.github/scripts/reset_failed.sh {RUN_ID}
   ```
3. Modify the container image in `CONTAINER_BASE_IMAGE.bioc` if system dependencies are missing

## How It Works

### Architecture Overview

The system consists of several key components:

1. **GitHub Actions Workflows**:
   - `run.yaml`: Main workflow orchestrating the build process
   - `update_readme.yaml`: Updates documentation and status

2. **Kubernetes Resources**:
   - Namespace: Isolated environment for each build cycle
   - PersistentVolumeClaim: Shared storage for built packages
   - Jobs: Individual package build tasks

3. **Scripts**:
   - Dependency resolution: `deps_json.R` analyzes package dependencies
   - Kubernetes management: `setup_k8s.sh`, `dispatch_k8s_job.sh`, etc.
   - Documentation: `update_readme.py`

### Workflow Process

1. **Initialization Phase**:
   - A new run ID is generated based on the current timestamp
   - The base Bioconductor container image is used to analyze package dependencies
   - Dependencies are saved as JSON files for processing
   - Kubernetes namespace and PVC are created

2. **Dependency Resolution & Build Scheduling**:
   - The system creates a dependency graph from the JSON files
   - Packages with no unsatisfied dependencies are identified for building
   - Each ready package is dispatched as a Kubernetes job

3. **Package Building Process**:
   - Each package is built in an isolated container
   - The container shares a volume where built packages are stored
   - Successfully built packages update the dependency graph
   - Newly satisfied dependencies enable additional builds

4. **Cycle Completion**:
   - When all buildable packages are processed, a PACKAGES index is created
   - The system preserves previously built packages not rebuilt in this cycle
   - The complete repository is uploaded to cloud storage via rclone
   - Statistics and completion time are recorded

5. **Documentation Update**:
   - Each cycle has its own README with detailed build results
   - The main README (this page) is updated with the cycles summary table

### Key Files Explained

- **GitHub Workflows**:
  - `.github/workflows/run.yaml`: Main build orchestration
  - `.github/workflows/update_readme.yaml`: Documentation updates

- **Scripts**:
  - `.github/scripts/deps_json.R`: Analyzes Bioconductor dependencies
  - `.github/scripts/find_ready_pkgs.py`: Identifies packages ready to build
  - `.github/scripts/dispatch_k8s_job.sh`: Creates Kubernetes jobs
  - `.github/scripts/handle_k8s_jobs.sh`: Processes completed build jobs
  - `.github/scripts/finish_cycle.sh`: Creates repository index
  - `.github/scripts/update_readme.py`: Updates documentation
  - `.github/scripts/reset_failed.sh`: Resets failed builds for retry

- **Configuration**:
  - `CONTAINER_BASE_IMAGE.bioc`: The base Bioconductor container image

- **Data Storage**:
  - `runs/{RUN_ID}/`: Data for each build cycle
  - `runs/{RUN_ID}/logs/`: Build logs
  - `runs/{RUN_ID}/README.md`: Detailed build status
